# General

Qt5 (`Core`, `Gui`, `Network`, `Widgets`) frontend for ZXTune. Entry point is `qt_app.cpp` (`Platform::Application`): it creates the `QApplication`, sets the single-instance dispatcher and the main window.

# Asynchronous execution

## Threads

- UI (main) thread - the `QCoreApplication` thread. `MainThread::IsCurrent()` is true only here.
- IO pool - `QThreadPool::globalInstance()`, several workers. Item parsing/opening runs here.
- Scanner thread - `Playlist::Scanner` runs a coroutine job (`Async::CreateJob`) off the UI thread. It emits `ItemFound`/`ItemsFound` with `Qt::DirectConnection`, so playlist item inserts happen on the scanner thread.
- Operation thread - `Playlist::Model::PerformOperation` runs an `Async::Activity` worker; runs are serialized per model (`WaitOperationFinish`).
- Sound backend thread - `Sound::BackendCallback` (`OnStart`, `OnFinish`, ...) is invoked from the backend's own thread.

Each `QObject` is bound to one of these threads (`QObject::thread()`); UI-owned objects live on the UI thread. `SelfThread::Execute` targets that thread.

## Dispatch helpers

`apps/zxtune-qt/supp/thread_utils.h`:

- `IOThread::Execute(obj, func, args...)` - runs on the global pool.
- `SelfThread::Execute(obj, func, args...)` - runs on `obj`'s thread: inline if already there, otherwise queued via `QMetaObject::invokeMethod` with `obj` as context, so a queued call is dropped if `obj` is destroyed first.
- `MainThread::IsCurrent()` - predicate/assertion, not a dispatch selector.

Both `Execute` forms capture a weak `QPointer` receiver guard and skip the call if the receiver is destroyed before it runs. `func` is either a member-function pointer (invoked on the guard's object) or a static/free function `R (*)(QPointer<S>, ...)`, which receives the guard as its first parameter. Arguments are converted to `func`'s parameter types up front, at bind time.

## Rules

- Do not capture raw `this` into a pool task. Dispatch with `IOThread::Execute(this, &Class::Method, args...)`; the guard is created at the call site, while the object is alive.
- When a worker blocks (parses/opens) and then re-dispatches to the object's thread, make it a static function that takes the guard explicitly and reuse it:

  ```cpp
  static void LoadItem(QPointer<Class> self, ...)
  {
    // blocking work
    SelfThread::Execute(self, &Class::Apply, ...);
  }
  IOThread::Execute(this, &Class::LoadItem, ...);
  ```

  A receiver alive at the entry check can still be destroyed while the worker runs; the guard captured at bind time is checked again on the trailing dispatch. Never rebuild a guard from a raw pointer mid-work.
- Module parsing/opening must not run on the UI thread. `ThreadCheckingService` enforces this with `Require(!MainThread::IsCurrent())`.
- Model notifications (resets, row changes) are marshalled with `SelfThread::Execute` so they run on the model's thread.

## Key files

- `apps/zxtune-qt/supp/thread_utils.h` - dispatch helpers.
- `apps/zxtune-qt/playlist/supp/model.cpp` - per-model storage lock (`SyncAccess`), `ChangeModel`, `WaitOperationFinish`.
- `apps/zxtune-qt/playlist/supp/data_provider.cpp` - `ThreadCheckingService`.
- `apps/zxtune-qt/playlist/supp/scanner.cpp`, `apps/zxtune-qt/supp/playback_supp.cpp` - scanner and backend callback threads.

# Build

Built by the repo-wide GNU make from `apps/zxtune-qt/Makefile`; the binary is `zxtune-qt` (Qt5 `Core/Gui/Network/Widgets`). Qt glue is generated by `make/qt.mak` into `objects_dir/.qt` - do not edit it:

- `ui_files` (`*.ui`) -> `*.ui.h` via `uic`
- `moc_files` (`Q_OBJECT` sources) -> `*.moc.cpp` via `moc`
- `qrc_files` (`*.qrc`) -> `*.qrc.cpp` via `rcc`

A `Makefile` in a subdirectory (`ui/`, `playlist/*/`, `update/`) adds that directory as a library via `ui_files`/`moc_files`/`ts_files`.

The GUI theme is picked at build time with `gui_theme` (`default` or `restorer`, default `restorer`), embedded as the `theme` Qt resource (`res/theme_$(gui_theme)`, `-DGUI_THEME=`). Translations: per-library `ts_files` (`*.ts`) -> `.qm` via `lrelease` (`make/l10n*.mak`), embedded into the binary; the `l10n/` sources are a non-goal per the root `AGENTS.md`.

# Layout

- `apps/zxtune-qt/` - `qt_app.cpp` (entry), `singlemode.*`, `app_parameters.h`, `urls.h`
- `apps/zxtune-qt/supp/` - app services: `options` (settings), `playback_supp`, `thread_utils`
- `apps/zxtune-qt/ui/` - widgets/dialogs: `controls`, `conversion`, `desktop`, `informational`, `preferences`, `tools`, plus `mainwindow`, `state`, `styles`
- `apps/zxtune-qt/playlist/` - playlist subsystem (`supp`, `io`, `ui`)
- `apps/zxtune-qt/update/` - self-update check
- `apps/zxtune-qt/res/` - GUI themes; `apps/zxtune-qt/dist/` - packaging (arch/debian/linux/rpm/macos)

# Settings

Persistent settings use the `Parameters::ZXTuneQT` namespace (prefix `zxtune-qt`): `app_parameters.h`, `ui/parameters.h`, `update/parameters.h`. `GlobalOptions::Instance()` (`supp/options`) is the process-wide container. `SINGLE_INSTANCE` toggles single-instance mode (`singlemode.*`). Site/help/bugreport/update-feed URLs are in `urls.h`.
